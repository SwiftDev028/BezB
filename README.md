# BezB — Digital. Without Limits.

Интернет-магазин цифровых товаров: Apple Gift Cards, Xbox, PlayStation, Steam и AI-сервисы.

> **Статус:** интеграция заказов с Supabase подготовлена. Каталог и цены в `src/data/products.ts` остаются
> тестовыми; база каталога намеренно пустая, поэтому реальные заказы не пройдут до загрузки проверенных товаров.
> Оплата не подключена, товары не выдаются. Названия игр вымышлены и служат местом под реальные товары.
> BezB не является официальным магазином Apple, Xbox, PlayStation, Steam, OpenAI или Anthropic.

## Стек

React 19 · TypeScript · Vite · Tailwind CSS 4 · React Router 7 · Lucide React · Motion for React · Vitest.
Шрифты (Oswald и Inter, с кириллицей) подключены локально через `@fontsource-variable` — без обращений к внешним серверам.

## Быстрый старт

Нужен Node.js 20+ (проверено на 22).

```bash
npm install        # установить зависимости
npm run dev        # запуск для разработки: http://localhost:5173
npm test           # тесты (корзина, фильтры, сортировка, форма)
npm run typecheck  # проверка TypeScript
npm run build      # production-сборка в папку dist/
npm run preview    # посмотреть собранный сайт локально
```

## Админ-панель заказов

Адреса: `/admin/orders` (список) и `/admin/orders/:id` (заказ). Ссылка есть в подвале сайта. Вход использует Supabase Auth;
допуск сверяется серверной функцией `is_admin()` и RLS.

- Список: поиск (номер, имя, email, товар), фильтры по оплате, выполнению и датам, сортировка, сводка.
- Заказ: статусы оплаты и выполнения вручную (с проверкой допустимых переходов), комментарии, поле «Информация о выдаче»,
  неизменяемая история всех изменений.
- Демо-сброс и создание тестовых заказов убраны из рабочего интерфейса.

**Оформление заказа → админка.** Checkout отправляет строки корзины в транзакционную RPC-функцию Supabase.
Сервер сверяет активность позиции и цену, рассчитывает сумму и выдаёт номер. Корзина очищается только после
подтверждённого ответа. Схема и подробная настройка описаны в [docs/BACKEND.md](docs/BACKEND.md).

**Ограничения.** Заказы доступны только после ручной установки миграции, настройки GitHub Actions и добавления
проверенных товаров. Оплаты и уведомлений нет; администратор не может помечать заказ оплаченным.

## Как изменить товары

Все товары — в `src/data/products.ts`. Добавьте запись через функцию `make({...})`:

```ts
make({
  slug: 'steam-topup-2000',        // уникальный адрес: /product/steam-topup-2000
  title: 'Пополнение Steam 2000 ₽',
  category: 'steam',               // apple | xbox | playstation | steam | ai
  platform: 'Steam / ПК',
  type: 'topup',                   // gift-card | game | subscription | topup
  price: 2190,                     // рубли
  description: 'Пополнение баланса Steam на 2000 ₽.',
  popularity: 70,                  // влияет на сортировку «По популярности»
  addedAt: '2026-10-19',           // влияет на «Новинки»
  // необязательно: oldPrice, badge ('popular' | 'new' | 'sale'), regions, available, restrictions, tags
})
```

Категории — `src/data/categories.ts`, баннеры слайдера — `src/data/banners.ts`, вопросы — `src/data/faq.ts`.
Когда появится API поставщика, замените содержимое `products.ts` загрузкой данных — интерфейс `Product` останется прежним.

Корзина и избранное хранятся в `localStorage` (`bezb:cart`, `bezb:favorites`). Товары, которых нет в каталоге,
из них автоматически игнорируются.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и отправьте проект:
   ```bash
   git add . && git commit -m "BezB prototype"
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` при каждом push в `main` запустит тесты, соберёт сайт и опубликует его
   по адресу `https://<user>.github.io/<repo>/`.

Как это работает:

- **`base`.** Vite берёт его из переменной `VITE_BASE`. Workflow задаёт `/<имя-репозитория>/` сам; локально и на
  собственном домене base — `/`. React Router получает тот же путь как `basename` (`src/main.tsx`).
- **Прямые ссылки и F5 на вложенных адресах.** GitHub Pages не умеет SPA-маршрутизацию, поэтому после сборки
  `scripts/postbuild.mjs` копирует `index.html` в `404.html`. Неизвестный путь отдаёт эту страницу, и React Router
  показывает нужный экран (или страницу 404). Статус ответа при этом 404 — это особенность статического хостинга.
- **Собственный домен или репозиторий `<user>.github.io`:** задайте `VITE_BASE=/` в шаге Build workflow.

## Ограничения

GitHub Pages — статический хостинг и не выполняет серверный код. Публичная отправка заказов работает через Supabase
PostgreSQL RPC; админский доступ ограничивается Supabase Auth и RLS. Переменные `VITE_*` публичны и не должны
содержать приватные ключи. Для оплаты и автоматической выдачи позже нужен отдельный серверный процесс.

## Чего пока нет (осознанно)

Реальной оплаты, backend и базы данных, аккаунтов пользователей, истории заказов покупателя, автоматической выдачи товаров,
настоящей (защищённой) админ-панели, нескольких языков и валют (форматирование цен уже вынесено в `src/utils/format.ts`),
реальных фотографий товаров — вместо них локальные заглушки (`ProductArt`).

## Перед запуском продаж

- Заполнить все места с пометкой **[Требует заполнения]**: реквизиты, контакты, условия, правила возврата,
  политику конфиденциальности (при необходимости — с юристом).
- Подтвердить законных поставщиков и право перепродажи каждого товара; описать способ получения.
- Заменить заглушки изображений на материалы с разрешённой лицензией.
